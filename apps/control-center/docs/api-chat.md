# 直连模型文本聊天

这是桌面助手 A2 的第一个实现：复用现有 Conversation、Run、消息流和停止入口。已有 CLI / RPC 席位继续承担本地项目执行。

## 配置与使用

1. 在「连接档案」创建或选择兼容 OpenAI Chat Completions 的连接，配置 API 基址和 API Key。密钥继续由服务端 ProviderStore 保存。
2. 在「运行席位」新建席位，执行方式选择「模型 API · 文本聊天」，显式选择连接并填写模型 ID。无需填写执行命令或推理档位。
3. 在成员管理中将一个助手绑定到此席位，然后从「新对话」选择该助手。
4. 输入文本即可开始。再次发送会沿服务端历史续聊；网页刷新或服务重启不会依赖浏览器缓存恢复上下文。点击停止会中断本机请求，可以继续发送新问题。

单助手文本会话无需添加 CLI 协调成员；群聊、任务流水线和原 CLI 主脑资格保持各自的校验规则。

## 协议与能力边界

- 使用 `POST /chat/completions`、Bearer 认证、SSE 文本流及 `stream_options.include_usage`；不使用 Responses、Anthropic Messages、Gemini 原生协议或 CLI OAuth 登录态。
- 基址带路径时保留该路径；只有域名时追加 `/v1/chat/completions`。使用完整地址时，在连接档案中声明 `isFullUrl`，路径必须以 `/chat/completions` 结束。
- HTTPS 是默认要求；本机回环模型服务允许 HTTP，但本版仍需要非空 API Key。自定义 HTTP 请求头和系统代理尚未接入此通道。
- 只支持单助手文本。图片、文件、网络搜索、工具调用、原生命令、本地写盘和远程 CLI 暂不支持；发送这些内容会明确拒绝，不把文件路径当作模型已读过的文件。
- 选择连接不会切换当前 CLI 供应商，也不会写入 CLI 的认证或配置。连接缺失、模型缺失或协议不兼容时停止派发，不自动改用其他供应商。
- 配置就绪与成功通信分别呈现；最近五分钟内收到完整回答且连接未变时才显示上游已验证。健康检查本身不主动发送计费请求。

## 上下文、输出与费用

上下文来自当前 direct Conversation 的 Run 链，只纳入同一助手已经完成的 API 文本问答。中断、失败和其他成员的消息不进入后续上下文；没有伪造 native CLI session。

每次请求最多 80 条历史及当前消息、128 KiB 文本上下文。达到上限或历史缺失会提示另开对话；历史记录保留，不静默截断。自动摘要和分支编辑属于后续 A2 工作。

每个运行席位的 API 执行器最多并行四个请求；多个席位共用连接档案时不合并计算此上限。响应有总超时、空闲超时、8 MiB 总流量和 256 KiB 单事件上限。只有有效 `finish_reason=stop` 与 `[DONE]` 才算完整回答；冲突结束、截断、拒绝、工具调用和异常响应保留为失败/部分输出。不会自动重放计费请求。停止只保证本机关闭请求，上游生成与计费状态以服务商记录为准。

输入、输出及总 token 按供应商回执持久化。无回执时显示未知，不推算 token 或价格；美元成本未知，现有美元预算闸不能当成该接口的计费硬上限。

## 验证入口

`node --test tests/api-chat.test.mjs` 覆盖真实本机 HTTP 流、UTF-8 分片、用量、截断、冲突终局、取消、超时、错误去敏和上下文归属。

`npm run qa:api-chat` 启动隔离控制面与本地模拟模型，真实操作页面创建席位、新建会话、流式回答、服务重启后续聊、停止、错误恢复和三种视口，报告及截图写到 `.qa-output/api-chat-*`。它不代表真实供应商或正式桌面已经验证。
