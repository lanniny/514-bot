# 514cc 产品定位与体验重构方案

> 日期：2026-09-05
> 状态：提案，待 LO 确认；本轮不实施产品代码。

> 本文是既有计划的产品决策收敛层，不另建一份竞争的全量 backlog。批准后把工作包映射回原任务编号，只保留一个执行队列。

## 1. 结论

**建议做产品体验级重构：重构主工作面、信息架构和视觉系统，保留执行内核、数据身份与安全契约。**

514cc 当前最值得放大的不是可接入多少 CLI，而是：用户能够围绕一个真实项目，把目标交给 AI，持续介入，最后拿到能够检查和继续使用的成果。

“可问责的 AI 协作台”作为内部品类定位延续；对用户用更直白的描述：**本地优先、成果可验证的 AI 项目工作台**。不再把内部治理术语、拓扑和配置层级作为理解产品的前置条件。

这一轮的重构重点不是把所有地方变得更华丽，而是让四个问题始终有答案：

1. 我在哪个项目，正在处理哪个目标？
2. AI 现在在做什么，有没有真正推进？
3. 有什么需要我决定，影响是什么？
4. 最终得到了什么，哪些已验证，哪些尚未完成？

## 2. 三个互斥方向

下表选的是唯一主心智模型，不是三套首页同时保留。

| 方向 | 核心用户与首屏 | 优点 | 必须接受的代价 | 判断 |
|---|---|---|---|---|
| A. 个人 AI 聊天工作台 | 轻量用户；联系人、历史消息、输入框 | 上手直观，视觉容易统一 | 项目执行、验证、权限容易变成聊天附件；难体现现有工程能力 | 不选为主方向，保留直接对话能力 |
| B. 可验证的 AI 项目工作台 | 独立开发者、技术负责人；项目、工作对话、待处理事项 | 与现有 Project/Conversation/Run、审批、证据、结算资产匹配 | 必须认真做完成标准、历史连续性与成果审阅 | **推荐** |
| C. 多 CLI 运行控制中心 | CLI 重度用户、运维；席位、供应商、队列、健康 | 能力暴露直接，配置管理强 | 用户先学系统再工作，页面长期像管理后台 | 收为高级设置与诊断，不当主入口 |

推荐首期服务对象：**单机上的个人专业用户**，先满足 LO 的反复使用，再验证对其他独立开发者的适用性。保留脱敏导出与分享能力，不在本阶段建设账号、多租户、在线团队空间。

核心场景优先次序：代码修复与功能迭代、独立评审与修正、技术调研与文档交付。CLI 接入、知识管理、自动化服务于这些场景，不各自争做一个产品。

以上是基于本仓资产与现有工作流的产品判断，不宣称某个细分市场没有竞品。本轮没有重新核验旧方案里的外部市场数字，不用它们证明战略正确。

## 4. 信息架构

### 4.1 主入口减法

一级入口收敛为 **工作、自动化、记录**；**设置**固定在独立位置。不是把所有现有功能删除，而是按任务关系重新归位。

| 入口 | 承载内容 | 现有能力归宿 |
|---|---|---|
| 工作 | 项目、工作对话、成员、当前任务、待处理事项 | Workbench 主入口；Bot 项目/对话能力合流；团队设置按需打开 |
| 自动化 | 定时任务、触发器、运行历史、失败处置 | automations、channels；不另建第二套调度系统 |
| 记录 | 跨项目运行记录、成果、成本、复盘、使用反馈 | sessions、observability、overview 的用户价值部分 |
| 设置 | 模型与连接、成员与能力、环境、权限与隐私、外观 | config、hosts、security、market 等管理能力 |

工作面内始终显示当前项目上下文，切换到设置后可返回原目标、草稿与滚动位置。不要把供应商、Adapter、席位的区别当成每个用户每次都要回答的问题。

`#bot`、`#conversation=`、既有配置深链先保留兼容。旧路由只做映射，不再维护一套独立业务选择状态。迁移期间同一目标只能有一个活动工作面。

### 4.2 对象语义不变

| 系统对象 | 用户理解 | 持久化责任 |
|---|---|---|
| Project | 工作项目与目录 | ProjectRegistry |
| Conversation | 一个可持续推进的工作对话；可私聊或项目群聊 | ConversationStore |
| Run | 为本次输入进行的一次执行 | Orchestrator |
| native CLI session | 执行连接的技术详情 | 现有 adapter/session 层 |

“任务”是用户目标的称呼，不额外引入一个与 Conversation/Run 争夺所有权的新数据库。一个工作对话可以多次执行，也可以暂时没有 Run。页签、筛选、密度是偏好，不充当业务真源。

项目允许零成员、零消息的草稿；点击创建不应偷偷启动执行。只有发送时才校验可执行成员。直接对话不能因视觉合并自动变成群聊。项目成员上限与单次 fan-out 上限继续分开。

## 5. 主工作面

### 5.1 桌面布局

```text
+-------------------+--------------------------------------------------+
| 514cc             | 项目 / 工作对话              状态   待处理   详情 |
| 工作 自动化 记录  +--------------------------------------------------+
| 搜索              | 对话 | 过程 | 成果                                |
|                   |                                                  |
| 最近项目          | 当前目标、消息与本轮摘要                          |
|   工作对话        | 过程事件按步骤折叠，不重复刷屏                     |
|   工作对话        |                                                  |
|                   | 有阻塞时出现明确的待处理操作                       |
| 已归档            +--------------------------------------------------+
|                   | 附件  输入目标                                    |
| 设置              | 接收对象  权限   运行设置                   发送 |
+-------------------+--------------------------------------------------+
```

默认两栏。左栏建议 256px，可拖动并记住偏好；主区 `minmax(0, 1fr)`。右侧详情是按需工作工具，不预留一个长期空着的装饰栏。

宽屏可打开约 360px 的文件/证据面板；窄屏采用互斥详情页或带焦点管理的抽屉。切换详情保留输入、选中对象和阅读锚点。不得用浮层盖住发送、停止或确认按钮。

“对话 / 过程 / 成果”是同一 Conversation 的三个视图，使用同一身份与事件来源。Run 切换器是本次/历史执行维度，不再混进 Agent 页签。成员详情按需查看，默认不要求用户逐个打开成员页收集答案。

### 5.2 三个必须先设计出来的真实场景

1. **执行中**：一个目标，两个成员分工，一项工具调用；清楚展示当前步骤、最近实际事件、耗时和可用介入动作。
2. **等待审阅**：目标和验收条件、变更文件、测试证据、独立评审结论、残余风险同时可达；成果预览占主要空间。
3. **配置连接**：左边可扫描的对象列表，右边编辑面；当前机器与生效范围固定可见，保存后显示实际生效状态。

原型用明确标注的代表性数据覆盖正常、空态、401、失败、断线、待审批和长内容。评审视觉不能只看“什么数据都没有”的欢迎页。

### 5.3 输入与运行

- 常驻只保留目标输入、附件、接收对象、有效权限和发送/停止。模型、effort、预算在“运行设置”内，摘要可见。
- 权限不得隐藏成一个模糊颜色点；沿用当前授权策略，不借视觉重构悄悄改默认权限。
- 简单任务直接提交；仅复杂任务或高影响动作展开目标/验收/影响核对，不强制每条消息先填表。
- 团队与常用参数可继承项目偏好；单次覆盖要可辨认，不能误存为全局默认。
- 提交中防重复，准入回执与开始执行分开；未知结果不自动重放。附件上传失败保留文本草稿。
- 所谓进度来自已登记步骤与实际事件；未知总量不画虚假的百分比。等待用户时不显示 AI 正忙的循环动画。

这里建议的是经新原型验证后的渐进式输入结构，不是重新执行 v49 已因缺乏收益而撤销的桌面参数套壳改造。

## 6. 视觉方向

**方向：安静、清晰、有工具质感的专业工作台。** 保留过去追求的阅读舒适与克制，不把暖色、磨砂、发光、衬线大字本身当成产品识别。

候选色板如下，属于待确认的替代方案，尚未覆盖 v47 已批准的暖纸视觉锁：

| Token 角色 | 候选值 | 用途 |
|---|---|---|
| canvas | `#F6F7F8` | 中性底色 |
| surface | `#FFFFFF` | 编辑与阅读表面 |
| text | `#20242A` | 正文与结构 |
| muted | `#667085` | 次要文字，仍须逐场景验对比度 |
| accent | `#176B5B` | 当前选择与主要操作 |
| link | `#315FA8` | 证据链接、引用与导航提示 |

暗色采用中性石墨底与清晰表面差，不做深棕全屏或蓝紫渐变。成功、警告、失败另用语义 token，始终搭配图标和文字；Agent 原生头像保留品牌识别，不能同时承担任务健康状态。

排版：中文优先系统 UI 字体，代码与命令使用等宽字体。默认 UI 14px、对话正文 15px、辅助文字不低于既有 12px 地板；紧凑面板标题 16-20px。字号不随视口宽度缩放，字距为 0；内容缩窄靠换行、分栏切换和局部滚动处理。

空间与组件：4/8/12/16/24px 间距体系，常规控件 32/36px 高，触屏关键热区至少 44px。常规圆角 4-8px；主区域不嵌套卡片，列表用对齐、行高和轻分隔线建立秩序。阴影只用于真正浮起的菜单、模态框和抽屉。

视觉资产：使用现有品牌资源、成员头像、真实文件预览、代码 diff、测试结果、文档或页面缩略图。不用无意义的星图、微光球、背景网格、粒子或大型几何插画填空。没有任务时显示最近项目和直接操作，不做营销首页或产品功能讲解页。

动效：优先表达展开、收起、状态变化和点击反馈，时长约 120-180ms；取消背景常驻动画和全员“呼吸”。尊重 reduced-motion、键盘焦点、高对比与用户字号偏好。

| 优先级 | 工作包 | 具体交付 | 不从零重做的资产 |

| P0 | 授权与加载状态 | 401 统一进入待授权态；停无效重试；保草稿；提供合法返回桌面/重新进入路径；未知不涂绿 | request/bootstrap、现有权限机制 |

| P0 | 成果审阅 | 对话目标、文件/文档预览、验证证据、风险、继续修正入口；区分已生成/已验证/待确认/已发布 | diff、artifacts、settlement、release record |

| P1 | 反馈闭环 | 在当前页面提交问题、查看受理与处理状态；说明附带哪些上下文，不默认抓取源码或凭据 | ProductFeedbackStore、现有反馈 API |

| P2 | 复盘与复用 | 目标类型、成功经验、失败说明和可审阅模板；用户确认后保存，不自动写项目记忆 | handoff、DELTA、已有记忆浏览和模板 |

成果完整性不能只按“有没有 diff”评判：代码任务看变更与测试，调研看来源与适用边界，文档任务看可编辑文件与渲染结果。现有 settlement 偏 Git worktree，应增加有类型的成果呈现契约，而不是把无代码变更的调研一概画成失败。

需要另行设计的高风险能力：协作级撤销必须绑定执行前基线与变更所有权，检测后续用户修改；不能把 `reset --hard` 包装成一键撤销。远程运行、未知归属和非可逆操作保持明确不支持或需要人工处置。

## 8. 完成标准与产品指标

**建议把北极星从“无需干预的 Run 比例”修正为“可核验的任务达成率”。** 无人干预可能意味着用户离开或没有发现错误，不是成功证明。

建议统计口径：同一目标下多次 Run 合并观察；验收条件满足且证据可打开才计入达成，主观标准需用户确认；运行中单列，取消和放弃单列，失败不因缺少证据而从分母排除。展示样本数与观察窗口，样本不足不做 Agent 排名。

配套指标：到首个有效成果的时间、找回既有对话的操作数、待处理项滞留时间、失败后恢复成功率、重新打开问题比例、可归集成本。必要审批不作为“干预太多”的负分，否则会诱导绕过安全。

DELTA 作为“独立检查带来了什么”的证据入口，不作为单一质量分或自动可信度评分。耗时节省与成本预测只能在有基准、样本和计费数据时展示区间；未知就显示未知。

## 9. 工程重构边界

保留 Node/REST/SSE、原生 ESM、Tauri 薄壳、现有 store、adapter、审批与交付协议。没有证据证明更换 React/Vue 或数据库就能解决当前主要体验问题，因此不把换框架作为前置。

前端以现有工厂与依赖注入方式收敛为导航壳、对话控制器、输入区、待处理、过程、成果、设置七类模块。只抽取当前迁移需要的 cohesive block，不按文件行数进行无收益拆分。

样式收敛到 token、基础控件、布局、业务组件和兼容层的明确所有权。不得再增加一个末尾全局 polish 覆盖层。若引入 CSS layers，先处理未分层旧样式的优先级和 `!important` 反转；不直接把一部分文件包入 layer 就宣称隔离完成。

迁移策略：隔离新工作面 -> 接共享只读投影 -> 接提交/恢复/审阅动作 -> 保留旧路由映射 -> 通过同数据跨入口回归 -> 默认切换。旧工作面在删除前保留回退入口；清理文件、存储迁移、发布与正式桌面替换仍单独确认。
