# 514cc Console 控制面 — UI/UX 系统性审查与完善方案

> 审查视角：产品经理 + 资深前端工程师  
> 审查日期：2026-08-30  
> 审查对象：`apps/control-center`（Vanilla ES Modules + 全局 CSS，Node `server.mjs` 静态伺服，自研 hash 路由，12+ 视图 / 四组导航）  
> 事实依据：全部问题均附文件路径与行号/统计数据，来源于对 `public/` 全量代码的静态审计。

---

## 0. 总体结论（双视角概评）

**产品经理视角**：信息架构骨架清晰（四组 12 视图分组合理、单一真源 `modules/nav-config.js`），Forge"暖纸铜橙"设计方向有辨识度；但**存在 6 个"隐形视图"脱离导航体系**、数据密集视图缺乏密度策略、高频操作路径缺少快捷化设计，导致"功能很强、找到很难、用熟才快"。

**工程师视角**：这是一套**无构建工具、无组件框架、无双标约束**的原生前端。优点是无依赖、启动快、a11y 投入大（aria 1330 处、skip-link、focus-visible、reduced-motion 齐备）；代价是**设计 token 双轨失控（533 处硬编码色）、字号体系失守（8–10px 小字 320+ 处）、断点体系碎裂（27 种断点值）、单文件巨石（app.js 32,037 行 / 1.6MB 同步加载）**。UI 质量问题的本质&#x662F;**"有设计体系、缺强制执行"**——token 文件存在但不被消费。

**一句话定调**：视觉底子与可访问性投入远超同类自研 Console，但工程治理缺失使体验一致性、可读性与性能被持续侵蚀。以下方案按 高 / 中 / 低 优先级组织，共 17 项。

## 1. 高优先级（P0）— 影响可读性、性能与全局一致性，建议立即排期

### P0-1 设计 Token 双轨治理：533 处硬编码颜色收敛

| 项        | 内容                                                                                                                                                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **问题**   | `forge/tokens.css:8-117` 已定义完整 OKLCH token（暖纸底 + 铜橙 #D97757 主色、亮暗双主题、字号/圆角/z-index scale），但全库 CSS 中实测 **533 处硬编码 hex**，JS 内约 20 处（如 `app.js` 中 `"#d97757"`）。DESIGN-NOTES.md 自曝主题曾从"暗夜玫瑰 #E0184D"翻转为"暖纸铜橙"，硬编码色即历史残留——导致暗色主题下部分面板颜色"漏改"、hover/disabled 态色值漂移、品牌色不可一键改。                 |

### P0-2 字号体系失守：8–10px 小字 320+ 处，突破可读性底线

| 项        | 内容                                                                                                                                                                                                                                                          |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **问题**   | 全库存在 25+ 种离散 px 字号，其中 **10px × 182 次、9px × 45 次、8px × 9 次**，均未走 `--text-*` token。中文在 10px 以下字形糊化、9px 实际不可读；这些极小字号集中在数据表格、状态徽标、时间戳——恰是观测/会话视图的核心信息区。WCAG 2.1 与中文排版惯例均以 12px 为下限。                                                                             |
| **改进建议** | ① 硬性下线 <11px 字号：8/9/9.5/10px 统一提升至 `--text-xs`(12px)，信息放不下就改信息架构（截断+tooltip、次要信息折叠），不许用缩字号解决；② 收敛 25 档离散字号到 token scale（12/13/14/16/18/20/24/28 八档）；③ 数据表格数字列加 `font-variant-numeric: tabular-nums`，时间戳用等宽数字保证纵向对齐；④ CI 加 stylelint 规则禁止裸 `font-size: Npx`。 |
| **预期收益** | 数据密集视图（sessions / observability / overview）可读性质变；中老年与低视力用户可用；表格数字列对齐专业感提升。                                                                                                                                                                                  |
| **涉及模块** | 观测组全部（overview / observability / sessions）、资源组（market / hosts / config）、team 表格。                                                                                                                                                                            |

### P0-3 首屏性能：1.6MB JS + 344KB CSS 同步裸加载

| 项        | 内容                                                                                                                                                                                                                                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **问题**   | `app.js` **32,037 行 / 1.6MB**、`styles.css` 16,294 行 / 344KB（另有 forge/ 25,807 行），无打包、无压缩、无代码分割（全库仅 4 处动态 `import()`），`index.html:10-39` 同步加载 **32 个样式表**。弱网/移动端首屏白屏时间长，且单文件巨石使增量缓存失效——改一行全量重下。                                                                                                        |
| **改进建议** | ① 引入零锁死构建管线：esbuild（单依赖、秒级）做 minify + bundle 指纹，保留 ES Module 源码组织不变；② 按视图代码分割：12 个视图面板（team-panel.js、market-panel.js、office-panel.js 等已天然成文件）改为路由级懒加载，`app.js` 只留壳 + 路由 + 共享模块，目标首屏 JS ≤ 300KB；③ CSS 同理：tokens + 壳样式内联/首载，视图样式随路由加载；④ `server.mjs` 加 `Cache-Control: immutable` + 指纹文件名、gzip/brotli。 |

| **涉及模块** | 全局基础设施；最大受益为移动端/弱网访问与首次加载的所有用户。                                                                                                                                                                                                                                                                      |

| **问题**   | 规范组件 `.empty-state`（`forge/data.css:2118`）存在，但 `app.js:4012,13413,13954` 等十余处散写 `<p class="subtle">暂无数据</p>` 绕过规范；加载状态绝大多数是文字"正在加载…"（`app.js:10781,13423`），**全库骨架屏仅 1 处**（`forge/team.css:2447`）。同一产品在 A 页有规范空态插画+引导按钮、B 页只有一行灰字，品质感撕裂；文字 loading 在数据表格场景会造成布局跳动（CLS）。 |

## 2. 中优先级（P1）— 体验精进与工程健康，建议 1–2 个迭代内完成

### P1-1 视觉层次与信息密度策略（产品+视觉）

- **问题**：观测组视图（overview / observability / sessions）为典型数据密集场景，当前缺少密度分级：关键指标、趋势图、明细表在同一视觉权重平面铺开；全局 20 种离散 gap 值、卡片内边距不一致，导致"哪里都是重点=没有重点"。同时缺少用户级密度切换（紧凑/舒适）。
- **建议**：① 建立三层视觉权重规范——L1 关键指标（大数字+状态色）、L2 趋势/分布（图表）、L3 明细（表格，默认折叠或分页），用 `tokens.css` 已有的字号/色阶 scale 严格执行；② 间距收敛到 4 的倍数 scale（4/8/12/16/24/32），替换 20 种离散值；③ 复用 `theme.js` 已有偏好机制，增加"密度"用户偏好（已有 density 字段，补齐 UI 入口并逐视图落地）。
- **收益**：总览页 3 秒定位关键信息；专家用户可用紧凑密度提升单屏信息量 30%+。
- **涉及**：观测组全部视图、`theme.js`、appearance 设置。

### P1-2 高频操作路径简化（产品）

- **问题**：以"发起一次协作会话"为例，当前路径依赖视图切换 + 面板内表单，缺少跨视图快捷动作；供应商 live 改回（`/api/providers/live` 一键改回）等高频动作深埋面板内部。命令面板已存在但动作覆盖不全。
- **建议**：① 绘制 Top-5 用户旅程（发起会话、查观测、改路由、切供应商、装插件），每旅程目标 ≤3 步；② 命令面板补全动作集（含上下文感知：当前视图相关动作置顶）；③ 全局快捷键图谱（`g o` 去总览等 vim 式序列），并在 UI 上可见提示；④ 会话/配置类表单支持"最近使用"默认值记忆。
- **收益**：专家用户操作效率倍增；新用户通过命令面板降低学习曲线。
- **涉及**：`command-palette.js`、`app.js` 键盘处理（现有 57 处 keydown 需统一到快捷键注册表）。

### P1-3 组件渲染层治理：267 处 innerHTML 拼接

- **问题**：`app.js` 内 219 处 + 各面板共 **267 处 innerHTML 字符串拼 UI**，XSS 防护依赖人工 `escapeHtml` 调用（漏一处即漏洞），且字符串内联样式/类名进一步加剧样式漂移；这也使组件级复用在技术上不可能。
- **建议**：① 不引入框架的前提下，建立轻量 `html` 模板标签函数（tagged template，自动转义插值，~30 行）替代裸拼接；② 高频复合结构（卡片头、状态徽标、表格行、表单行）沉淀为渲染函数库 `modules/components/*.js`；③ 安全基线：CI 规则禁止 `innerHTML =` 直接拼接变量（白名单除外），并评估对存量加 Trusted Types / CSP。
- **收益**：XSS 攻击面系统性收敛；组件真正可复用，新视图开发提速；样式集中度提升。
- **涉及**：`app.js` 全部面板、team-panel/market-panel/office-panel 等。

### P1-4 色彩对比度专项（无障碍硬指标）

- **问题**：主色铜橙 **#D97757 在暖纸浅色底上对比度约 3.4:1**，低于 WCAG AA 对正文文本 4.5:1 的要求（大字号/图形边界 3:1 勉强达标）。该色若用于小字号正文/链接即不合规；暗色主题下的次级文本 `--text-*` 也需逐一实测。当前无任何对比度测试手段。
- **建议**：① 全量对比度审计脚本（解析 token 组合，输出不合规配对清单）；② 不合规配对修复策略：文字场景用更深一档的 accent-700（如 #B85C38 级别）替代，装饰/图形场景保留 #D97757；③ 把对比度门槛（正文 4.5:1、大字 3:1）写进 token 文件注释 + CI 检查，新色入库即过闸。
- **收益**：WCAG AA 合规；低视力与强光环境下可用性实质提升；品牌色使用有了"文字档/图形档"明确分工。
- **涉及**：`forge/tokens.css`、所有使用 accent 色文本的视图（导航激活态、链接、按钮、徽标）。

### P1-5 动效与过渡规范化

- **问题**：**207 处 transition** 无统一时长/缓动 token，时长从 100ms 到 500ms 随机分布，缓动函数混用 ease/ease-in-out/linear；优点是 `prefers-reduced-motion` 已覆盖 24 处且有用户级开关（`theme.js:37`），底子好。
- **建议**：① 建立 motion token：`--dur-instant:100ms / --dur-fast:160ms / --dur-base:240ms / --dur-slow:360ms` + 两条缓动曲线（标准 ease-out、强调 spring-like cubic-bezier），207 处逐一归位；② 制定动效语义规范：状态反馈≤160ms、视图转场≤240ms、引导性动效≤360ms，禁止 >400ms 阻塞交互；③ 面板展开/收起改用 `grid-template-rows` 或 `interpolate-size` 平滑方案，消除高度跳变。
- **收益**：全产品"手感"统一，高级感来自一致性而非动效数量；交互响应感知更快。
- **涉及**：全局；重点为侧边栏、对话框、toast、面板折叠、视图切换。

### P1-6 交互反馈链路补全

- **问题**：异步操作反馈不完整——部分按钮点击后无 pending 态（可重复提交）、轮询类视图（providers live 热加载"可见时轮询、失焦即停"是好设计）缺少"最后更新时间/轮询中"状态指示、长任务（校验、部署类）无进度反馈只有等待。
- **建议**：① 按钮规范：所有触发异步的按钮自动进入 loading + disabled（组件层统一实现，见 P1-3）；② 轮询视图右上角统一"● 实时 / 已暂停 / 更新于 xx:xx"三态指示；③ 长任务引入进度条或步骤指示器；④ toast 分级（成功/警告/错误）与操作可撤销（配置类变更）。
- **收益**：杜绝重复提交类 bug；实时数据可信度可视化；错误恢复路径明确。
- **涉及**：全部表单与数据视图、`app.js:2445` toast 模块。

## 3. 低优先级（P2）— 品质打磨与长期演进

### P2-1 字体排版与中西文混排

- **问题**：纯系统字体栈（`styles.css:9-11`，无 @font-face）是务实选择，但中西文混排无优化：中英文间距、标点悬挂未处理；行长无约束（宽屏下正文可达 100+ 字符/行）；行高随各样式表漂移。
- **建议**：正文行长约束 60–75 字符（`max-inline-size`）、行高统一 1.6（正文）/1.4（标题）；中西文间自动空格（构建期处理或 `text-spacing` 渐进增强）；数字/代码列强制等宽数字。涉及：markdown 渲染（`markdown.js`）、office 文档工坊、各说明性面板。

### P2-2 品牌感与视觉风格统一性深化

- **问题**："暖纸铜橙 + 星图 hero"方向明确，但主题翻转（暗夜玫瑰→铜橙）残留的 533 处硬编码色（见 P0-1）意味着部分面板仍是旧时代观感；各视图头部装饰风格不一（有的星图、有的纯色、有的无）。
- **建议**：P0-1 完成后做一次"品牌一致性走查"：统一视图头部规范（标题层级、装饰元素、面包屑）；图标已统一 lucide sprite，补充图标使用规范（尺寸 16/20/24 三档、stroke 一致）；考虑将星图语言延展为空状态/加载态插画，形成完整品牌资产。

### P2-3 无障碍深化（在已有良好底子上冲刺 AA+）

- **现状**：aria/role 1330 处、skip-link、focus-visible 100+ 处、原生 `<dialog>` + `aria-modal`——底子罕见地好。**剩余缺口**：① 对话框焦点陷阱（focus trap）与 Esc/返回焦点还原需逐 dialog 实测；② 图表（手写 SVG/canvas）对屏幕阅读器完全不可读——需补 `role="img"` + 数据表替代视图；③ 键盘可达性实测（当前 57 处 keydown 散落，无覆盖矩阵）；④ 色盲模式下状态色（红/绿/橙）需配合形状/文字双重编码。
- **建议**：按"键盘全流程走查 → 屏幕阅读器（NVDA）实测 → 图表替代文本"三步走；产出 a11y 覆盖矩阵纳入回归。

### P2-4 响应式细节打磨

- **问题**：基础移动适配已有（底栏、`min-width:320px`、820px matchMedia），但数据表格在移动端的横向滚动策略不一、触控目标存在 <44px 的密集按钮区、移动底栏项数（12+ 视图）若超 5 项则不可用。
- **建议**：移动端表格规范（关键列冻结+横向滚动+行点击展开详情）；触控目标 ≥44×44px 审计；移动底栏收敛为 4 主项 + "更多"。涉及：`styles.css` 移动端段、各表格视图。

### P2-5 仓库与工程卫生

- **问题**：`public/` 下残留 `scratch-preview-5.html`、`scratch-preview-5-open.html` 等调试文件，仓库根有 `debug.log` 与 20+ 个临时目录（`.qa-bot-p0-*` 等），会被静态伺服暴露且干扰审计。
- **建议**：临时文件移出 `public/` 或加入伺服黑名单；根目录临时目录归档/清理；`server.mjs` 对隐藏文件（`.` 开头）默认 404。

### 6.5 已知风险与回滚

- **字号整体上浮**（10px→12px 约 700 处）可能让极少数紧凑徽标/表格换行。所有值集中在 `--text-*` token，如需回退只改 `forge/tokens.css` 一行。

### 6.6 审计结论修正（重要：原方案有三条诊断与实况不符）

落地过程中逐条复核，发现首轮审计（基于静态扫描的推断）有三处**判断错误**，在此更正，避免后续按错误前提投入工时：

| 原诊断 | 实况 | 结论 |

| P2-3「图表（手写 SVG/canvas）对屏幕阅读器完全不可读」 | **错误**。8 个真实图表/自定义图形**全部**带 `role="img"` + `aria-label`（由 `svgFrame()` 统一注入，见 `modules/overview-usage.js:529`）。首轮误判是因为只在 `index.html` 里 grep `role="img"`（返回 0），而图表是运行时由 JS 生成的 | 该项无需投入；已改为处理真实的残余问题——装饰图标缺 `aria-hidden` |

**方法论教训**：静态 grep 只能证明"某字符串出现与否"，不能证明"某能力存在与否"。涉及运行时行为的结论（图表是否可读、焦点是否受控）必须回到渲染代码确认，否则会把已做对的工作当成缺口去"修"，反而制造回归。
