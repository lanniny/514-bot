## 1. 五个结构性风险（先修地基，再盖楼）

### R1 · Git 证据链断裂（致命 / P0）
宪法 §二.5 Integrity Gate 要求「区分我认为和我验证了」。当 `.git` 与账本承诺脱钩，`D-2026-08-18-013` 的 v42 must-ship 闭包、R3-01 release record 全部失去可回溯落点。**且 2910 文件挤在单提交 = 无法 bisect、无法 blame、无法按里程碑回退。**

### R2 · 巨石债务（P1，但复利最重）
`orchestrator.mjs` 323KB + `providers.mjs` 191KB + `app.js` 1.58MB。这三个文件是每次改动的必经之路。当前靠 176 个契约/e2e 测试兜底，但**契约测试能防回归，不能降低认知负荷**。新人（和新 agent）接入成本已经失控。

### R3 · 短期记忆过期（P0，成本最低）
`context.md` 落后 11 天，而它恰恰是「每个 Agent 接入时先读这里」的入口。**过期记忆比没有记忆更危险**——它让 agent 带着错误前提自信执行。

### R4 · 版本真源漂移（P0，纯决策成本）
v3.5.0 vs 实际 v4.x。悬置越久，新 agent 误判成本越高。这是**唯一一个纯拍板就能关闭的风险**。

### R5 · 治理层停滞 vs 产品层狂奔（P1）
8 月下旬 121 个 handoff 几乎全是 control-center/bot 产品波次；治理面（rules/module/skills）自 v3.5 无实质演进，`control_center.phase2` 的 P1（路由信号外置合一 + summoned 审计闭环）仍挂账。**产品跑得越快，治理落后越远，最终产品会失去它是"514cc"而非"又一个 AI 客户端"的理由。**

### W1 · 解耦波（建议 3–5 天，风险最高，收益最久）
原则：**增量解耦 + 契约护栏，不暂停产品、不整体重写**。

| 项 | 动作 | 风险与护栏 |
|---|---|---|
| W1-1 | `orchestrator.mjs` 323KB 按职责切分：session lifecycle / dispatch / event fanout / settlement / recovery | 每切一刀跑全量测试；先补契约测试再动刀 |
| W1-2 | `providers.mjs` 191KB 切分：adapter registry / normalization / stream parse / capability probe | adapter 契约测试现存（adapters.test.mjs 99KB），可复用 |
| W1-3 | `app.js` 1.58MB 前端模块化（复用 `public/modules/` 既有雏形） | **先加构建或 ESM 原生加载决策** |
| W1-4 | `index.html` 295KB 模板化拆分 | 服务端渲染片段 or 客户端模板 |
| W1-5 | CSS 治理：把 OPAQUE-PROBE 从「玻璃透出」推广为**全模块 CSS 契约基线** | 现有 ambient-ui-contract 可复制模式 |
| W1-6 | 类型层：JSDoc typedef 或生成 `.d.ts`（191KB providers 无类型 = 重构高风险） | 渐进，不阻塞 |
| W1-7 | 依赖注入/服务定位器，消除隐式耦合 | 低优先，可后置 |

**关键前置决策**：是否引入构建步骤（esbuild / vite）。
- 保持 no-build：部署简单、Tauri 壳直接加载，但 1.58MB 单文件不可持续、首屏杀手。
- 引入构建：可拆包/树摇/压缩，但增加构建-部署链路与调试成本。
**倾向**：引入**极薄** esbuild 打包（仅 bundle + minify，不做转译），保持无框架。
