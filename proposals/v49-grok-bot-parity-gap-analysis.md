## 0. 结论先行

**总体判断：语义层与骨架已达「大概一致」目标；剩余差距集中在四个可数的地方——假数据残留、发送主链未接、运行历史空转、真实 provider 未验收。**

对标完成度按五维评估（满分 = Grok Bot 同维度水准）：

| 维度 | 完成度 | 一句话判断 |
|---|---|---|
| 对话理解/生成 | **架构超越 / 验证滞后（80%）** | 多模型异构真身协作全球罕见，但 bot 面真实 provider 端到端从未跑过 |
| 回复风格 | **95%** | 消息流、打字指示、协作过程渲染、审批卡、交接板全真数据 |
| 功能丰富度 | **75%** | 四大语义面全落地；Channels/私有技能/runHistory 三处半成品 |
| 交互体验 | **85%** | Grok 式三栏、预览+日期+错误态全绿；小屏与导览缺 |
| 响应质量 | **结构性优势（90%）** | DELTA/结算/证据/回放是 Grok 没有的东西 |

**重要更正**：此前记录的桌面端「1-3 分钟全灭」（B-01 嫌疑）今日实证为宿主任务收树假症状——18:34 启动的实例稳定 >5 分钟，18:43 用户手动重启的实例独立存活至今。桌面稳定性问题大概率已随 09-08 重编解决，pet overlay 嫌疑降级。

## 1. 五维深度对比

### 1.1 对话理解/生成能力（80% · 架构强、验证弱）

| 能力 | Grok Bot | 514cc | 差距 |
|---|---|---|---|
| 底座模型 | Grok 单系（含 voice、媒体生成） | 9 adapter 异构真身 CLI（Claude/Codex/Grok/Kimi/Pi…），社会模拟+流水线双编排 | **514 架构胜**，但依赖用户自备 CLI 与 key |
| 多 agent 会话 | Bot 群聊、@点名、kickoff 模板 | 同构落地：bus 消息总线、@点名菜单、kickoff 解析器、单 owner 守卫 | 语义一致 |
| 上下文管理 | 黑盒 | context-claims、compaction、steer、轮间插话、成员快照 | 514 更透明 |
| **端到端验证** | 产品级 | **bot 面真实 provider 会话 = 0 次验收**（QA 全部隔离内核 + fixture，CLI 不存在轮次即失败） | **最大质量缺口** |

### 1.2 回复风格（95%）

消息气泡/Markdown、头像与身份、打字指示（三球）、协作过程折叠时间线、审批卡、提问卡、交接板、恢复条——全部真数据渲染。QA 14 检查覆盖。剩余差距仅为群聊打字指示的成员级区分（现在只认会话级 run 状态）。

### 1.3 功能丰富度（75%）——**本轮分析的主战场**

已落地（真数据+测试+QA 截图）：Bot 定义（job/standingRules/审批边界/技能/配额）、Routines（六要素/test run/automation 桥接/启停删）、交接（kickoff/handoff/ack/交接板）、列表预览+日期徽章、错误态+重试、插件市场、自动化页、观测页。

**半成品与假数据（经代码复核，全部可数）：**

| # | 位置 | 现状 | 证据 |
|---|---|---|---|
| G-1 | 私有技能编辑器 | **硬编码假数据**「Inbox triage / Summarize and label incoming mail」，增删改不落盘 | `index.html:638` 一整段静态 DOM + `app.js:20060-20227` 只操作 DOM |
| G-2 | Channels 区 | 硬编码空态「还没有连接频道」，后端 `/api/channels` 真源存在但右栏不读 | `index.html:529` |
| G-3 | composer 多 @ 派发 | 前端 API 封装就绪（`bot-collab-api.js:110`）但 composer 发送主链不调用——用户无法从输入框发 kickoff | app.js 零调用点 |
| G-4 | routine 运行历史 | `appendRunHistory` 存储就绪，但 automation.triggered 事件无人订阅回填——历史永远空 | `routines.mjs:480` 存在、无订阅方 |
| G-5 | 从成功 run 沉淀 skill | 无通道（Grok「save as skill」） | — |

**明确不采用**（protocol §6 已拍板，不重开）：云计算机、Bot 建 Bot、公开分享链接、录屏教学、语音。这些不是缺口是边界。

### 1.4 交互体验（85%）

已完成：Grok 式三栏骨架（左栏项目树+成员/搜索/筛选、顶栏、中栏消息流+composer、右栏会话详情）、移动返回按钮、命令面板（Ctrl+K）、键盘细节（Cmd+Shift+I 会话详情）。

差距：390px 小屏未走查（新 dialog/交接板流式布局未实测）；命令面板只索引 11 项（v48 P-18 既有结论）；无产品导览（v48 P-19）。

### 1.5 响应质量（90% · 结构性优势）

Grok Bot 没有而 514 有的：DELTA 问责账本、事件哈希链、run 结算卡、证据索引、回放 scrubber、预算止损闸、adapter 健康度。这些是 v48 主张的品类差异化内核，本轮不动。

## 2. 优先级改进计划

排序原则：**假数据零容忍 > 主链接通 > 历史可见 > 新能力**。每项标注预期波次规模（一刀 = 一晚主驾+QA 收口）。

### P0 · 对标收尾（假数据清零 + 主链接通，≈2 刀）

| ID | 任务 | 内容 | 验收 |
|---|---|---|---|
| **W1** | 私有技能真实化 | G-1：私有技能接真源（挂 `/api/bots/<id>` profile.skills 或独立 store），编辑器增删改落盘，删硬编码示例 | 契约测试演进 + QA：创建→编辑→删除→刷新读回 |
| **W2** | composer kickoff 路径 | G-3：群聊输入框多 @ 消息（≥2 个点名成员）→ 发送时走 `/api/bots/relay/kickoff` 而非普通 run 创建；单 @ 或无 @ 走既有路径不变 | QA：群聊发「@A 做 X @B 做 Y」→ 交接板出现两条 task |
| **W3** | routine 运行历史接线 | G-4：事件订阅 automation.triggered → 按 automationRef 反查 routine → appendRunHistory；Routines 行展开显示最近 3 条 | 单测 + QA：enable 后手工 trigger → 历史 1 条 |
| **W4** | Channels 真数据 | G-2：右栏 Channels 区读 `/api/channels`，空态文案由后端真源驱动 | 契约测试 |

### P1 · 质量验证（≈2 刀）

| ID | 任务 | 内容 | 验收 |
|---|---|---|---|
| **W5** | **真实 provider 端到端** | 正式实例（本机已有 CLI/key）跑通：单聊 1 轮（任一 adapter）+ 群聊 kickoff 1 轮 + routine enable 后真触发 1 次。这是 1.1 表格里唯一的空白格 | 三条真实会话截图 + 事件流核验（复刻 QA 断言于正式实例） |
| **W6** | 小屏走查 | 390px 视口过一遍 bot 面：新建例行 dialog、交接板、成员设置表单 | qa:ui 四视口全绿 |
| **W7** | 群聊打字指示成员级 | 群会话中区分「哪个成员正在输入」 | 契约测试 |

### P2 · 超越项（对齐 v48 路线图，不新增编号）

- 从成功 run 一键沉淀 skill（G-5，衔接 v48 P-05 知识复利域）
- bot 面命令面板索引扩充（v48 P-18）
- 产品导览/能力地图（v48 P-19）
- 价值证明卡进结算（v48 P-01/P-02）

P2 全部已有 v48 编号与路线，本提案只声明先后：**P0/P1 完成前不动 P2**——对标收尾优先于自我超越。
