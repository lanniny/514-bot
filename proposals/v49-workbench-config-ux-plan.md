| # | 我错说了什么 | 实测真相 | 我错在哪 |
|---|---|---|---|

## 1. 三个真问题（全部实测，非印象）

### 1.1 🔴 字号地板被自己的密度公式击穿

这是本轮**唯一的可读性缺陷**，也是收益最高的单点。

`forge/tokens.css:92` 明文写着硬下限与理由：

> UI-AUDIT P0-2：**12px 为硬下限**（中文 10px 以下字形糊化、不可读）

而 `forge/experience-polish.css:2117` 把 `--text-xs` 在内容面重定义为：

```css
.main-content, .page-heading, .settings-card, .md-body, .message-body {
  --text-xs: calc(var(--ui-font-size, 14px) * 0.79);
}
```

`--ui-font-size` 是**用户可拖的滑杆**，区间 12–18px（`app.js:1141` clamp）。逐档算：

| 滑杆 | `--text-xs` 实际值 | vs 12px 下限 |
|---|---|---|
| 12px | **9.48px** | ✗ 击穿 2.52px |
| 13px | **10.27px** | ✗ 击穿 1.73px |
| **14px（默认）** | **11.06px** | ✗ 击穿 0.94px |
| 15px | **11.85px** | ✗ 击穿 0.15px |
| 16px | 12.64px | ✓ |
| 17px | 13.43px | ✓ |
| 18px | 14.22px | ✓ |

**默认档就在违规区**，且用户把字号往小调时越violating——与滑杆的语义预期一致（他要更小），但击穿了项目自己认定的可读性底线。

协作台首屏实测叶子文本字号分布（共 93 个）：

```
 11.1px    53   57%  #########################
   12px    16   17%  ########
 12.5px     7    8%  ###
   13px     7    8%  ###
   14px     4    4%  ##
   16px     1    1%
   28px     4    4%  ##
   36px     1    1%
```

**57% 的可见文字在 11.06px**。这不是"偏小"，是低于本项目为中文字形定的下限。

**为什么门禁没拦住**：`scripts/ui-lint.mjs:34` 的规则是

```js
const BARE_FONT_RE = /font-size\s*:\s*[0-9]*\.?[0-9]+px\b/g;
```

它只认字面 `font-size: Npx`。而违规形态是**自定义属性的重定义**（`--text-xs: calc(...)`），且 `CUSTOM_PROP_DEF_RE`（L33）会主动跳过所有 `--` 开头的行。**门禁结构上不可能拦到这一类**。

这正是 `intent-without-mechanical-carrier` 的形状：`forge/README.md` 的层叠契约明文写了「颜色 + 尺度令牌由 `tokens.css` 独占，**any other file** 不得触碰」，但**零机械消费者**——没有任何一条 lint 规则或测试在检查它。

`capability-bus`（97px）是**教学性质**的——首次访问讲清"三层各写各的真源"很有价值，第 20 次访问就是纯噪音。而它没有折叠。

### 1.3 🟡 设置轨的 6 个入口通向同一个视图，但看起来是 6 个地方

设置轨 21 项，其中 **6 项** `data-view="config"`，只是 `configSurfaceJump` 不同：

| 轨项标签 | 落点 |
|---|---|
| 连接 | `config` / `sources` |
| 运行席位 | `config` / `sources`（**与「连接」同一个面**） |
| 本机运行时 | `config` / `local-runtime` |
| 技能 | `config` / `capabilities` + `capWorkspace=skills` |
| MCP 服务器 | `config` / `capabilities` + `capWorkspace=mcp` |
| 钩子 | `config` / `hooks` |

它们在轨里**平铺**，分散在「基础设置」「资源」「Agent 能力」三个不同分组下。用户点「技能」和点「MCP 服务器」，落到的是**同一页的同一个 tab 容器的两个 tab**——但轨上没有任何视觉线索表明这件事。

副作用已写在测试里：`scripts/qa-ui.mjs:71-72` 的注释

> `.first()`：v4 设置侧栏同一视图有多个跳转入口（连接/技能/MCP/钩子/本机运行时/运行席位都是 `data-view="config"`），严格模式单元素假设已过时

—— QA 脚本被迫加 `.first()` 绕开歧义，这是 IA 问题在测试层的回声。

## 2. 协作台方案

> 原则：**骨架层密度守恒，冲击力加在抬头处**（承接 `ui-elevation-plan` §零的判断，不重复论证）。
> 下列 W-* 项按「可读性 → 密度 → 叙事」排序，不按视觉冲击排序。

### W-01 · 字号地板修复（🔴 最高优先，属地基不属美化）

`experience-polish.css:2117` 三行改为带地板的形式：

```css
.main-content, .page-heading, .settings-card, .md-body, .message-body {
  --text-base: var(--ui-font-size, 14px);
  --text-sm: max(12px, calc(var(--ui-font-size, 14px) * 0.89));
  --text-xs: max(12px, calc(var(--ui-font-size, 14px) * 0.79));
  --text-lg: calc(var(--ui-font-size, 14px) * 1.14);
}
```

`max()` 是 Baseline 稳定特性，无需回退。效果：滑杆 12–15px 档位下 `--text-xs` 钉在 12px，16px 以上恢复线性缩放。

**代价要说清**：滑杆调小时，`xs` 档与 `base` 档的比例会被压缩（12/12 = 1.0），层级感变弱。这是**故意的取舍**——层级感可以靠字重与颜色补，可读性没有替代品。若 LO 认为层级更重要，替代方案是把地板设在 11px 并同步修正 `tokens.css:92` 的注释（**但那等于承认下限写错了**，需要显式决定，不能默默改）。

**必须同时落机械承载**（否则这条修复会被下一次"顺手优化"抹掉）：见 §4.1 与 §4.2。

### W-02 · composer footer 从 6 个平级控件收为 1 + 展开

现状：附件 · 模型(173) · Effort(173) · 权限(103) · 预算(173) · 发送 —— 717px 塞在 754px 里。

四个参数胶囊（模型/Effort/权限/预算）**语义同类**：都是"这一轮怎么跑"。合成一个「运行参数」胶囊：

```
┌──────────────────────────────────────────────────────────┐
│ [+]   描述目标 · @ 点名 · / 命令 · Ctrl+K 面板              │
│                                                          │
│ [+]  ⟨Sonnet · high · 写盘 · $0.75 ▾⟩      Enter 发送  [↑]│
└──────────────────────────────────────────────────────────┘
        └── 单个胶囊，展开后是 2×2 网格（复用 composer-cli-console 已有的展开体例）
```

- 折叠态显示当前四值的紧凑摘要（一行，`--text-xs` 修复后 12px 可读）
- 点开展开为 2×2 网格，四个 `pick-menu` 原样复用，**零新组件**
- 权限档（Plan/Review/Build）是**安全语义**，折叠态保留独立色标（写盘=琥珀），不与其他三项等价压平

收益：桌面从 95% 占满降到约 45%，为窗口变窄留出余量；移动端从换行（100px）回到单行。

**风险**：多一次点击才能改模型。缓释——摘要文字直接可点即展开（整条胶囊是热区），且 `composer-cli-console` 的「席位默认」已能一次性设定常用值，逐轮改动本就是少数场景。

### W-03 · 右栏（mission-dock）默认可发现性

右栏 `#mission-control-dock` 默认 `aria-hidden + inert`，宽 400px 却完全不可见。首次访问的用户不知道存在一个"环境信息 / 任务上下文"面板。

方案（择一，见 §6 待拍板 3）：
- **A（推荐）** 默认收起但保留 28px 竖向手柄条，标注「环境」，点击展开——把"存在"变成可见，把"内容"留在展开后
- **B** 首次访问自动展开一次，用户手动收起后记住偏好（`project-prefs-store.js` 已有存储层）
- **C** 保持现状，仅在顶栏开关加 badge 提示未读事件数

### W-04 · 纯图标按钮的触屏可达性

22 个纯图标按钮全部有 `title` + `aria-label`——键盘与读屏没问题，**触屏没有 hover**，`title` 完全不可达。

不是全部都要加文字。按频次与后果分三档：

| 档 | 按钮 | 处置 |
|---|---|---|
| 高频且形义明确 | 发送(↑)、附件(+)、搜索 | 保持纯图标 |
| 低频 | 管理团队、筛选、新会话 | 加 `--text-xs` 文字标签（修复后 12px 可读，这是 W-01 的红利） |
| **高危** | 取消任务、清除已结束任务 | **必须**加可见文字 —— 纯图标的破坏性操作在触屏上等于盲点 |

### W-05 · 空状态接叙事层（唯一的"美化"项）

协作台可见空状态 3 处，是全站最适合放展示轨的落点：`.empty-state` 不参与密度竞争，放大字号零可用性风险。

```css
.empty-state strong { font-size: var(--display-xs); line-height: var(--leading-display-snug); }
```

`v47` §5 已规划 5 套纯 SVG 品牌插画（星图罗盘 / 折叠棱镜 / 古铜挂锁 / 平衡印章 / 星轨断链）。本方案**不重复设计**，只指出协作台的 3 处空状态是它们的第一批消费者，并把展示轨消费从 17 处往上推。

### C-03 · 设置轨的层级化

6 个 `data-view="config"` 入口从平铺改为父子：

```
配置图谱                      ← 一级（点击落 sources 面）
  ├ 连接与席位                ← 二级（合并现「连接」+「运行席位」，二者本就同一个面）
  ├ 能力（Skill / MCP）
  ├ 钩子
  └ 本机运行时
```

- **「连接」与「运行席位」落点完全相同**（都是 `config`/`sources`），合并为一条，消除"两个入口一个地方"
- 二级项缩进 + 左侧连接线，视觉上表明"通向同一页的不同分区"
- 副产品：`qa-ui.mjs:71` 那个被迫加的 `.first()` 有了收敛的前提（本方案不改 QA，只是让它未来能收紧）

`settings-rail-chrome.js:21-41` 的 `syncSettingsRailActive` 已经在处理"多入口同亮 + `aria-current` 唯一"，层级化后这段逻辑更自然：一级亮 + 当前二级亮。

### C-04 · 配置页空状态补齐

实测：协作台 3 处空状态，**配置页 0 处**。加载中 / 扫描无结果 / 权限不足时是裸空白。

至少补三处：能力扫描无结果、钩子未配置、运行时未探测到。复用 `.empty-state compact-empty` 体例，与协作台一致。

## 4. 机械承载（本方案的核心，不是附录）

> 上面每一条改进如果只靠"记得别改回去"，就是下一次退化的候补。以下三条是**机器强制**。

### 4.1 `ui-lint` 新规则：`token-redefine`

`forge/README.md` 的层叠契约明文写着颜色/尺度令牌由 `tokens.css` 独占，**目前零机械消费者**。补上：

```js
/* forge/tokens.css 之外的文件重定义尺度令牌 —— 层叠契约的机械承载。
   README「Single sources of truth」表此前只是文档承诺；experience-polish.css:2117
   把 --text-xs 改成 calc(--ui-font-size * 0.79)，在默认档产出 11.06px，
   击穿 tokens.css:92 自己写的 12px 硬下限，而既有五条规则**结构上**都拦不到：
   bare-font 只认字面 font-size，bare-hex 主动跳过所有 -- 开头的行。 */
const TOKEN_REDEFINE_RE = /^\s*--(?:text|display|space|radius|dur)-[\w-]+\s*:/;
```

基线制照旧：现存重定义计入基线（`experience-polish.css` 的密度覆盖是**有意设计**，不是错误——它需要的是地板，不是禁止），新增即失败。

### 4.2 `qa:ui` 新断言：全滑杆档位的计算字号地板

静态 lint 算不出 `calc()` 的运行值——这条必须实测：

```js
// 滑杆 12→18 逐档，断言无叶子文本 < 12px。
// 为什么是实测：违规值由 calc(var(--ui-font-size) * 0.79) 在运行时产生，
// 静态扫描看到的只是公式。11.06px 这个数字任何静态工具都得不到。
for (const size of [12, 13, 14, 15, 16, 17, 18]) { /* setUiFontSize → 扫叶子文本 */ }
```

**元验收**（防恒真基线）：把 `max(12px, …)` 改回裸 `calc(…)`，本断言必须变红。不做这一步，这条断言可能永远为真而毫无价值——`tautological-test-baselines` 那条教训的落点。

### 4.3 首屏 chrome 预算断言

`qa:ui` 已有长任务双层预算的体例（`qa-ui.mjs:44-56`），照抄一个空间预算：

```js
const CHROME_BUDGET_RATIO = 0.4; // 首个正文块的 y 不得超过视口 40%
```

现状 65% 会立即失败 → 应在 C-01 落地后再启用该断言，**不要先加断言再改代码**（那会让门禁在中间态一直红，人就会习惯性跳过它）。
