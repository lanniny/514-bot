# 514 Bot 协作方法与渲染体系

日期：2026-09-07。延续 collaboration-fusion-20260905.md 和 Bot 唯一入口决策；本轮面向桌面端。

## 产品判断

514 Bot 是以持续对话为入口的项目协作工作台。借鉴最初 Grok Bot 设计输入中的短消息、统一联系人、渐进展开的执行详情；特色落在有责任人的分工、有来源的交接、有证据的复核。未确认具体上游版本，不对其官方能力作事实断言。

用户日常只需发目标、补充限制、回答必要问题和审阅成果。过程页回答“谁在做什么、卡在哪里、上一手交给了谁”；成果页回答“交付了什么、复核指出什么、还有什么未完成”。保留现有权限、附件、成员、历史、审批、恢复与高级工具能力。

## 协作方法

| 方法 | 适用工作 | 调度与收束 | 当前边界 |
|---|---|---|---|
| 单席直达 | 简单问答、明确的小任务 | 已有 simple 路由一轮返回 | 路由结果决定，不按问候关键词另造分类器 |
| 执行与复核 | 边界清楚的实现、分析 | 计划 -> 执行 -> 交叉复核 -> 有余量时汇总 | 已有 pipeline；复核不等于验收通过 |
| 补强后汇总 | 有明确缺口的复杂任务 | 同上，deep 分支在保留汇总轮次时补强 | 补强输出不标作再次独立复核 |
| 按需协作 | 项目群聊、需要多个成员提供输入 | 明确收件人 -> 有界队列 -> 交卷 -> 协调者收束 | 现有 social 顺序消费队列，不宣称并行执行 |

方法通过现有路由、pipeline/social 与 standard/deep 实现；本轮不加入一个只改文案而不改调度的模式按钮。私聊、项目群聊拓扑继续由服务端决定。

### 交接要求

- 派工应包含目标、责任范围、可用输入、依赖、交付物和验收依据；只有独立工作才适合并行。
- 接收者返回结论、证据、实际执行状态和阻塞；不得把上一位成员的自述当作验证证据。
- 复核必须对照原始目标，允许推翻执行结论；汇总完整保留执行、复核、补强三份输入。
- 补强必须说明哪些意见已处理、哪些仍未处理；轮次或预算不足时保留复核结论并标记缺口。
- 工具/MCP 属于席位能力，CLI/harness 才是运行后端。Grok Search 不恢复为席位。
- 角色建议是 prompt 层协作方法。权限、预算、深度、重放与任务所有权仍由既有后端闸门执行。

## 桌面呈现

沿用中性底色 #ffffff / #f8f9fa，正文 #24282e，次级 #5c6470；执行态用 #176347，复核/链接用 #255da2，阻塞使用现有语义警告色。字体继承现有本地 sans，标题 18px、正文 14px、辅助 12px，不跟随视口缩放。

```text
项目树 | 对话标题 / 当前或历史运行
       | 对话    过程    成果
       | 目标与运行状态
       | 协作方法 / 执行中 / 待处理 / 已结束
       | 分工与执行记录        | 责任成员
       | 委派与交接时间线      | 轮次与限制
       | 同一个消息输入框
```

所有区域是同一工作面的平铺内容，使用分隔线、留白和稳定列宽。无嵌套页面外壳、悬浮大卡片、虚构流程动画或百分比。

## 渲染与数据契约

- Project -> Conversation -> Run -> native session 不变。历史使用 Run 的成员快照；当前 Conversation roster 不覆盖历史责任。
- 新建纯投影模块把已有 taskGraph、turnAttempts、result 转成语义明确的展示模型；展示模型不写入运行状态。
- 原始委派 ID、attempt ID 与 task ID 保留，可展开核对。未知状态显示“状态未知”，不用绿勾兜底。
- 执行结束、存在复核、发生补强、目标验收分别呈现；run.succeeded 不自动等于成果通过。
- 任务和交接每页各 50 条。过滤、分页、展开、焦点属于视图偏好；在 Run/Conversation 更换时复位，流式更新中保留。
- 渲染器拥有过程页子区域，不复用完整 Bot/Workbench 页面。通过既有 escaped Markdown、Lucide 和增量节点协调器呈现。
- UI 从 service snapshot 读取真实次数；social 无正式复核事件时不从自然语言猜测复核状态。

## 后续编排演进

真正并行应先补结构化任务包的依赖/读写范围、资源锁、独立 worktree、取消传播和 join 收束，复用现有 taskGraph/attempt/claim，不新增任务数据库。并发任务若触碰相同写范围必须排队；不能只把 socialLoop 改为 Promise.all。

持久化验收应作为独立业务动作，绑定 Run、成果版本、验收条款和证据；接受者与执行状态分离。当前版本只展示已有复核与未闭环事实，不添加一个没有证据绑定的“已验收”按钮。

Ask/恢复/原生命令的旧桥接仍按原路线继续抽取。本轮验证不代表正式桌面替换、真实 provider/MCP/SSH 或发布完成。
