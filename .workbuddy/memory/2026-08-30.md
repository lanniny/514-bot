## P0 事故：.git 对象库损毁与重建

**现象**：`git` 突然报 `fatal: not a git repository`。检查发现：

- `.git/refs/` 整个目录消失，只剩空壳
- `.git/objects/pack/*.pack`（2 个）被删，只剩 `.idx`
- 松散对象从 ~3200 个掉到 9 个

**最可能成因**：`git fetch` / `git commit` 触发的自动维护（`gc --auto` /
`maintenance run --auto`）被 SIGTERM 打断。repack 的流程是「先写新 pack →
再删旧 pack 与已被打进 pack 的松散对象 → 再整理 refs」；中途被杀，就会
两头落空。时间线吻合：事故发生在一次被 120s 工具超时 SIGTERM 的命令之后。

**教训（硬约束）**：
1. 长会话里先 `git config gc.auto 0 && git config maintenance.auto false`，
   手动、离峰再 `git gc`。已在本仓设置。
2. 不要对可能触发 auto-gc 的 git 命令套短超时；要跑就放后台。
3. 破坏性操作前的 `.git` 全量备份不是形式主义——这次全靠它。

**恢复过程**（可复用）：
1. `git ls-files`/reflog 取证：`.git/logs/HEAD` 与 `.git/logs/refs/heads/main`
   保留了完整 SHA 序列；`FETCH_HEAD` 保留了远端 SHA。reflog 是最后的地图。
2. 从 `I:/514claude/_git-backup/514cc-git-20260829-2339` 合并回松散对象
   （`cp -Rn backup/objects/. .git/objects/`，用 `-n` 不覆盖现有文件）。
3. 移走孤立的 `.idx` 和 `multi-pack-index`（其 .pack 已不在，留着只会让
   git 报错）。
4. 重建 refs。注意：**`git update-ref` 对 `refs/remotes/*` 静默失败（exit 0
   但不落盘）**，改用 shell 重定向直接写文件才成功。原因未查明，记一笔。
5. 本地 main 指向无效对象时 `git fetch` 会报 `did not send all necessary
   objects`——先把 ref 落到一个有效 SHA 再 fetch。
6. `git read-tree HEAD` 重建索引。**这一步会把远端仍在跟踪的运行时产物
   重新灌回索引**（.scratch/ 1291 个、.qa-output/ 102 个），必须紧接着
   `git ls-files -c -i --exclude-standard -z | git update-index --force-remove -z --stdin`
   再清一次。

## 03:46 F-048 event-store 追加式哈希链（提交 ff014db）

**查证**：`#hashes()` 是布隆过滤器双哈希、480 行 "chain" 是 Promise 链，均非审计链。
此前的事件日志**改一条删一条都无从发现**，而 514cc 整套证据链纪律建立在这些事件之上。

**实现**：每条事件带 `prev`（前一条链哈希，首条 genesis）+ `hash`
= `sha256(prev + "\n" + 本行 JSON)`。新增 `verifyChain()` 与 init 后的 `chainStatus`。

**三个关键取舍**：
1. **对原始行文本哈希，不经过 JSON 往返**。常见做法 parse→删 hash→重新 stringify→哈希
   会被外部工具重排版触发误报（把"格式变更"报成"被篡改"）。改用 lastIndexOf 定位 +
   切片清空 hash 值后哈希，写入与验证看到同一份字节。
2. **占位符回填**（`"hash":""` → 算哈希 → 回填），省掉一次完整对象序列化。
   prev/hash 恒为最后两个键，保证定位不被 data 内同形文本误导（有专项测试）。
3. **链尖必须在第一个 await 之前同步推进**，否则并发 emit 读到同一个 prev 而断链
   （40 条并发写入测试专锁此点）。写入失败记 chainFault 且**不回滚**链尖——
   未落盘却推进链尖，后续 prev 指向文件中不存在的哈希，verifyChain 必然报
   prev-mismatch。**让故障持续可见，比悄悄自愈更重要。**

**遗留升级**：38551 条历史行 → legacy 段（不参与校验也不算断裂），新事件从 genesis 起新链。
真实 24MB 文件 init 286ms → 293~347ms（+10~20%），纯哈希 101ms/38550 行。

**🔴 能力边界**：能检测改内容/删条目/删头部/插入；**无法**检测"拿到写权限后重算整条链
并全量重写文件"，剥掉 hash 字段也会让该行退化为遗留行而通过。
要防住需**外部锚点**（把 chainTip 定期固化到进程外）——这是下一步最高优先级。

   `self-asserted`）+ `clientActor`（请求体自称，留档但不得当证据）。

   `denyAll`/`denyRun`/`expire` 的终态事件补 `actionSha256`，三类终态形状对齐。
