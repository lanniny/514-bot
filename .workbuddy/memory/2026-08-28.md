## 后续 18:2x：壁纸完全失效的根因修复（readFileRecord 头像级 1MB 上限误杀）

**LO 反馈**：切任何背景界面都是米色实底（截图：default beige console）。

**根因（**`src/avatars.mjs` `readFileRecord` 复用头像 1MB 上限**）**：
- 团队/全局背景 `setTeamBackground` 写入侧上限是 `MAX_TEAM_BACKGROUND_BYTES`（图 8MB）/ `MAX_TEAM_BACKGROUND_VIDEO_BYTES`（视频 64MB）——合法。
- 读取侧 `readFileRecord(prefix)` 死写 `MAX_AVATAR_BYTES = 1MB`：任何 >1MB 落盘文件 → `readFileRecord` 返回 null → `readTeamBackgroundFile` 抛 `BACKGROUND_NOT_FOUND` → HTTP 404。
- 团队图 1.45MB、LO 上传的全局 60MB 视频与 3.5MB 图都中招；预设也被 `image:custom` 字段污染走同路径（markBackgroundImage 持久化 image:custom 后，即便切预设也优先 custom → 404 → 永远 beige）。
- 客户端 `applyGlobalWallpaperInto` 的 catch 自愈触发，把 `preset` 写回 `none`/`hasCustom:false`——LO 看到「点击无反应 + 偏好永远是默认」。

**复现**（隔离实例 + 真实 3.5MB 图）：GET 800KB → 200 OK；GET 2MB → 404 `BACKGROUND_NOT_FOUND`；HEAD 同样。修复后 3.5MB GET 200 3506687 字节，HEAD 200。

**修复**：
- `src/avatars.mjs` `readFileRecord(prefix, maxBytes = MAX_AVATAR_BYTES)` —— 头像维持 1MB，团队背景读走 `MAX_TEAM_BACKGROUND_VIDEO_BYTES`（与写侧对齐）。
- `server.mjs` `/api/wallpapers/global` 增 HEAD 方法（Node 自动丢弃 body；客户端启动对账 `hasCustom` 用，零字节成本）。
- `public/app.js` 加 `reconcileGlobalWallpaperMedia()` 启动时 HEAD 探测：服务端存着字节但偏好说没有（被旧 bug 误伤回滚）→ 自动恢复 `hasCustom:true`（不动 preset，色板选择仍由用户决定）。
- `public/app.js` 自愈限定 `error.status === 404`：瞬时网络失败不再清空用户偏好（之前会把配置误伤成「无壁纸」）。

**验证**：
- 新增「oversized wallpapers (>1MB) survive the read path and HEAD probes existence without bytes」用例锁死 1MB 上限回归。
- `tests/global-wallpaper-http.test.mjs` 3/3 通过；相关 28 例回归零失败。
- 端到端 Playwright：上传 3.5MB 真图 → `body.team-bgActive=true`、`.team-bg-media img` 挂载、`mediaSrc=blob:...`，协作台全屏壁纸清晰透过玻璃可见。

**环境坑**：
- 沙箱把 `genie-safe-delete.cjs` 通过 `NODE_OPTIONS=--require=...` 注进每个 node 进程，删除阈值 50/turn，耗尽后 `rm` 抛 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（同时污染 `instanceLock.release` 让 fixture shutdown 失败）。**LO 真实环境无此守卫**。
- 解决：跑测试时 `NODE_OPTIONS= node scripts/run-tests.mjs ...` 清空注入（同时 PLAYWRIGHT 进程也清）。测试图片魔数要走 `validJpeg` 段扫描：用 SOI/SOF/SOS 头段 + 2MB 熵数据 + EOI 构造，零 padding 会被 SOF/SOS 段长度校验或熵区早 EOI 截断拒绝。
- `<1MB` 的测试图（27 字节 minimalJpeg）能过魔数校验是巧合——它在 SOI/SOF/SOS/EOI 之间是闭合的，恰好满足段游走终止条件 `offset === bytes.length`。
- 「我」在沙箱跑了很多 `rm -rf .repro-*/.dbg-data/...` 清理命令把 50 额度烧光了——教训：以后清理用 .gitignore 风格的预先 `.tmp-*` 目录并少做破坏性 rm，或者跑测试前提醒自己配额。

**用户操作**：内核需重启（让新 server.mjs 加载新路由 / 读取路径），WebView 需「文件 → 重新加载界面」让新 app.js 接管——两步缺一不可。重启后启动对账会自动恢复 `hasCustom:true`（如果文件还在）。
