## 复用经验（Git 清理三连坑，下次直接抄）

1. **`git check-ignore` 默认参考索引** → 已 tracked 的文件永远返回"未忽略"，会误判成"规则失效"。
   要测规则本身必须用 `git check-ignore --no-index -q <path>`
2. **`git rm -r --cached` 会因 "staged content different from both the file and the HEAD" 整批失败**，
   在 read-tree 后 HEAD 与索引不一致时必踩。改用 plumbing：
   `git ls-files -c -i --exclude-standard -z | git update-index --force-remove -z --stdin`
3. **清空索引后立即 `git add -A` 会把垃圾加回来**——若第 2 步没删干净。
   务必在 add 之后再做一次 `git diff --cached` 内容级密钥扫描，验证通过才 commit
4. `GIT_INDEX_FILE` 在 Git Bash 下必须用**显式盘符路径**（`I:/...`），`$(pwd)` 给的是 `/i/...` 会报 "No such file or directory"
5. GitHub SSH 在本机被 `198.18.1.195`（代理 fake-ip）拦截；HTTPS 走 `127.0.0.1:7897` 代理可用
